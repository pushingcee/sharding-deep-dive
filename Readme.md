### Overview

--------
## About the project

This project is a hands-on playground and a way for me to explore and confirm my understanding of sharding in a practical way. It's inspired largely by DDIAs chapter on sharding along with Notion's blog article "Herding Elephants".

The initial idea, as with all things, was to just **implement** what I've read about. However, with time it grew.
The long-term vision for this experiment is to:
1. Implement sharding in the following ways: manual and via Citus
2. Currently here -> Compare both approaches to single instance performance, however it's going to be in "constrained" Docker containers in order to make the performance differences more noticeable in smaller datasets
3. Implement a migration pipeline from a single PostgreSQL database to a Citus sharded database (Herding Elephants)
4. Try applying load on constrained databases via some "heavy queries" and Locust

The data generator supports three modes of operation:
- single database
- manually sharded database
- Citus sharded database

### Explored ideas
- [X] Moving from a single database to a sharded database:
  Key learnings:
    - Significant overhead; serial keys can no longer be used
    - You have to think about data tenancy - are related rows from different tables on the same database? If not, you're forced to create "joins" at the application level, which is for people who are smarter than me
    - Key selection is crucial - make sure to select a key/logic which isn't going to be concentrated on a single shard
- [X] Manual table sharding based on a function:
    - Easiest to implement in the Python script; however, if I have to move the data after it's generated, it would be more painful
    - Learned that some people in production have a special table where they store the ID of the data and the ID of the shard, making it easier to change or migrate down the line
- [X] Manual table sharding based on a function + lookup table

```sql
-- Heavy cross-shard analytics query
WITH user_order_stats AS (
    SELECT 
        u.user_id,
        u.first_name,
        u.last_name,
        u.country,
        COUNT(o.order_id) as total_orders,
        SUM(o.total_amount) as total_spent,
        AVG(o.total_amount) as avg_order_value,
        MAX(o.order_date) as last_order_date,
        COUNT(CASE WHEN o.status = 'delivered' THEN 1 END) as delivered_orders,
        COUNT(CASE WHEN o.status = 'cancelled' THEN 1 END) as cancelled_orders
    FROM users u
    LEFT JOIN orders o ON u.user_id = o.user_id
    WHERE u.created_at >= CURRENT_DATE - INTERVAL '6 months'
    GROUP BY u.user_id, u.first_name, u.last_name, u.country
),
product_performance AS (
    SELECT 
        p.product_id,
        p.name,
        p.category,
        p.price,
        COUNT(oi.order_id) as times_ordered,
        SUM(oi.quantity) as total_quantity_sold,
        SUM(oi.quantity * p.price) as total_revenue,
        COUNT(DISTINCT o.user_id) as unique_customers
    FROM products p
    LEFT JOIN order_items oi ON p.product_id = oi.product_id
    LEFT JOIN orders o ON oi.order_id = o.order_id
    WHERE o.order_date >= CURRENT_DATE - INTERVAL '6 months'
    GROUP BY p.product_id, p.name, p.category, p.price
),
country_analytics AS (
    SELECT 
        u.country,
        COUNT(DISTINCT u.user_id) as total_users,
        COUNT(DISTINCT o.order_id) as total_orders,
        SUM(o.total_amount) as total_revenue,
        AVG(o.total_amount) as avg_order_value,
        COUNT(DISTINCT p.product_id) as unique_products_ordered
    FROM users u
    LEFT JOIN orders o ON u.user_id = o.user_id
    LEFT JOIN order_items oi ON o.order_id = oi.order_id
    LEFT JOIN products p ON oi.product_id = p.product_id
    WHERE u.created_at >= CURRENT_DATE - INTERVAL '6 months'
    GROUP BY u.country
)
SELECT 
    'User Analytics' as report_type,
    COUNT(*) as total_users,
    SUM(total_orders) as total_orders,
    SUM(total_spent) as total_revenue,
    AVG(avg_order_value) as overall_avg_order,
    COUNT(CASE WHEN total_orders > 10 THEN 1 END) as high_value_customers
FROM user_order_stats
UNION ALL
SELECT 
    'Product Analytics' as report_type,
    COUNT(*) as total_products,
    SUM(times_ordered) as total_orders,
    SUM(total_revenue) as total_revenue,
    AVG(total_quantity_sold) as avg_quantity_sold,
    COUNT(CASE WHEN total_revenue > 10000 THEN 1 END) as top_products
FROM product_performance
UNION ALL
SELECT 
    'Country Analytics' as report_type,
    COUNT(*) as total_countries,
    SUM(total_orders) as total_orders,
    SUM(total_revenue) as total_revenue,
    AVG(avg_order_value) as avg_order_value,
    COUNT(CASE WHEN total_revenue > 50000 THEN 1 END) as top_countries
FROM country_analytics;
```
